# QQ 群聊管理

面向 AstrBot `qq_official` / `qq_official_webhook` 适配器的 QQ 官方群聊管理插件。插件复用 AstrBot 已认证的 QQ 客户端，覆盖 QQ 官方当前提供的群管理与群聊富媒体接口，并支持 QQ 原生群指令面板；不读取、保存或输出机器人凭据。

## 要求

- AstrBot `4.27.3 <= version < 5`
- QQ 官方机器人 WebSocket 或 Webhook 适配器
- 调用者是 AstrBot 管理员
- 机器人已获得 QQ 群管理接口白名单权限
- 入群审批、禁言和自动审核要求机器人是目标群管理员
- 按钮审批需要 QQ 自定义按钮和互动事件权限

## 安装

在 AstrBot 插件管理页使用仓库地址安装：

```text
https://github.com/mgz0227/QQGroup-admin
```

插件没有额外 Python 依赖。

### 更新与配置保护

更新后，已登记但暂未绑定群的欢迎规则、全局关键词和全局策略作用域会保留，群重新绑定后自动生效；未绑定期间不会执行这些规则。真人验证会先独立发送包含用途、纯数字回退和撤回说明的文字提示，再发送按钮卡；按钮卡也会显示验证用法和算式，兼容会折叠键盘卡前置消息的客户端。

AstrBot 更新时会替换插件代码目录，正常情况下不会修改 `data/config` 中的插件配置。为避免配置文件因重装、磁盘恢复或手工清理而被按 schema 默认值重建，插件会在 AstrBot 持久 KV 中保存一份有界的入群审核快照，包含已绑定群、欢迎规则和全局策略。检测到任一配置列表缺失、类型错误或被重建为空时会分别自动恢复；WebUI 主动保存为空列表则视为明确操作，不会自动恢复。启动迁移不会覆盖旧快照，即使插件状态 KV 损坏也会继续读取独立快照。快照不保存 B 站 Cookie 等敏感凭据。

如果更新后看到群条目仍在但 QQ 官方自动审核显示关闭，通常是审核模式被 WebUI 的旧页面或“关闭/条件审核”同步操作改写，而不是配置列表被删除。请在目标群重新打开 `/审核设置`，选择需要的模式并点击“应用当前配置”；插件不会在普通重载时主动删除 QQ 官方策略。

## 命令前缀

插件使用 AstrBot 自带的唤醒前缀，不再设置 `/群管` 根命令。将 AstrBot 的 `wake_prefix` 配置为 `/` 后，可以直接发送：

```text
/群信息
/上传群文件 https://example.com/demo.png [文件名]
/申请列表
/审核设置
/同步指令面板
/禁言 @成员 2h
/禁言@成员 45
/撤回 5
/撤回 @成员 3
/全体禁言
/全体解禁
/自动审核状态
```

如果使用其他唤醒前缀，只需替换命令开头的 `/`，命令名称不变。

## 命令

多个 QQ 号码使用英文逗号分隔。成员优先使用 `@成员`，也可以填写成员 OpenID。

| 命令 | 作用 |
| --- | --- |
| `/群帮助` | 显示命令帮助 |
| `/群信息` | 查询群信息，并显示当前群和自己的 OpenID |
| `/上传群文件 <URL> [文件名]` | 通过 QQ 官方富媒体接口发送公开 URL 文件；按扩展名识别图片、视频、语音或普通文件 |
| `/机器人状态` | 查询机器人群角色和消息接收状态 |
| `/申请列表 [游标]` | 每页查询 5 条待审申请，并显示同意/拒绝按钮 |
| `/审核设置` | 显示审核模式、UID、条件组合、兜底动作和应用按钮；默认 45 秒后自动撤回 |
| `/同步指令面板` | 创建或更新面向机器人所有群的 QQ 原生管理指令面板 |
| `/禁言状态` | 查询全员规则和当前成员禁言 |
| `/禁言 <成员OpenID\|@成员> <时长>` | 新增或更新禁言；纯数字按秒，也支持 `30m`、`2h`、`7d` |
| `/禁言@成员 <时长>` | 无空格写法，纯数字按秒 |
| `/解禁 <成员OpenID\|@成员>`、`/解禁@成员` | 解除成员禁言 |
| `/撤回 <数量>` | 撤回本群最近最多 50 条已收到的普通成员消息 |
| `/撤回 <成员OpenID\|@成员> [数量]` | 撤回指定普通成员最近最多 50 条消息 |
| `/全体禁言`、`/全体解禁` | 查询当前全员规则并说明 QQ 官方群 OpenAPI 的写入限制；不会伪造执行结果 |
| `/自动审核状态` | 查询当前群自动审核状态 |
| `/自动审核开启 <QQ号,...>` | 创建或启用当前群策略，并添加白名单 |
| `/自动审核添加 <QQ号,...>` | 添加白名单，并扫描已有待审申请 |
| `/自动审核移除 <QQ号,...>` | 移除白名单 |
| `/自动审核同步 确认` | 将当前群的 WebUI 配置同步到 QQ 官方 |
| `/自动审核关闭 确认` | 删除当前群策略及其白名单 |

`/同步指令面板` 只管理带有本插件专属备注的全局群面板，不覆盖其他面板。面板包含 `/审核设置`、`/申请列表`、`/禁言状态`、`/机器人状态` 和 `/上传群文件`，5 项都只允许群主或管理员点击；点击后仍需发送已填入输入框的命令。重复执行会更新原面板。

## 多群管理页面

插件会在 AstrBot WebUI 的“插件页面”中增加“QQ群审核管理”。页面按真实群名称列出所有已绑定群，支持搜索、多选、批量编辑和批量应用，也可为每个群独立配置：

- 群 OpenID
- 是否启用 QQ 号码白名单策略
- 是否启用条件审核、B 站 UID 检查及有效 UID 直接通过
- 通过关键词、硬拒绝关键词、全部/任一条件和未通过时的兜底动作
- 同步后是否扫描已有待审申请
- 审批按钮的默认拒绝理由
- 条件审核轮询间隔
- 单群关键词回复
- 群级基础消息审查、单群关键词回复（连续图片/复读由运行配置中的按群全局策略统一管理）
- 全局和单群成员黑名单/白名单；支持成员 OpenID、联合 OpenID 和已绑定的 B 站 UID，黑名单优先于白名单
- 可按群选择的全局策略中的连续图片/表情阈值、跨成员人数、时间窗、最多撤回数量和复读随机禁言区间
- 可按群选择的全局消息频率限制：时间窗、触发条数、撤回数量、回复模板和艾特开关
- 图片文字关键词审核（全局/单群），可选本地 OCR 或视觉 OCR 模型；视觉模型返回对象或 JSON 字典均可正确读取
- 入群欢迎规则：支持多条消息、按已绑定群选择、成员艾特和欢迎消息自动撤回

页面分为“群管理”“全局规则”“运行配置”“身份验证”四个视图。插件所有可操作配置都在此页面提供；平台实例、QQ 策略 ID 和运行游标等内部状态只由插件维护，不提供手工编辑。身份验证页使用折叠卡片而非长表格，支持按名称、B 站 UID、成员/联合 OpenID 和群名称/OpenID 搜索，每页可选 10、20 或 50 条。

使用步骤：

1. 在每个目标群发送 `/审核设置`。
2. 群主或群管理员点击“绑定此群”，插件会从 QQ 官方接口读取真实群名称并登记当前平台；也可以直接点击“启用条件审核”完成绑定和启用。
3. 打开 WebUI 的“插件页面 -> QQ群审核管理”，编辑对应群并保存。
4. 点击该群的“应用”，或回到群内再次打开 `/审核设置` 并点击“应用页面配置”。

群可以逐个在各自群聊中绑定，数量不受单个输入框限制，也不需要在后台手填群 OpenID。页面不会创建未绑定群，避免把错误 OpenID 应用到其他群。

两种自动审核不能在同一群同时启用。QQ 原生白名单可能在插件读取验证消息前直接放行，因此同步命令会拒绝这种配置。

WebUI 保存的是期望状态。绑定后修改条件会在下个周期生效；切换 QQ 白名单策略需点击“应用”。插件隐藏记录策略 ID、平台 ID 和上次成功应用的白名单，后续只增删名单差异。批量编辑只覆盖明确选择的字段，空文本只有勾选“覆盖”时才会清空原值；单次最多选择 100 个群，超大白名单需分批处理。批量应用会逐群执行，汇总成功/失败数量并显示首个失败原因。

“运行配置”可设置轮询间隔和按群生效的全局策略。全局策略按列表顺序匹配，每份策略都可以选择多个群；群范围留空表示覆盖全部已绑定群，后续新增群也会自动纳入。拒绝关键词、黑白名单、连续发图、复读随机禁言、消息频率限制、撤回模板、艾特开关和关键词回复冷却/撤回时间可以按群配置；AI 主模型、多回退模型、阈值、图片审核和 OCR 始终是单份全局配置，并在策略列表上方的独立“全局 AI 内容审核”面板维护，不会随策略切换、增加或删除而复制或清空。策略范围重叠时以前面的启用策略生效，页面会提示重叠群；群内设置按钮修改共享策略时会自动拆出当前群专用策略，不会影响同一策略中的其他群。旧版顶层全局字段首次保存时会迁移为“默认全局策略”，不需要重新填写。

旧版顶层全局字段仅保留用于兼容和迁移，已从 AstrBot 通用配置页隐藏；请在插件页面的“运行配置”中维护策略，避免多个入口互相覆盖。图片视觉引用规范化使用独立有界预算，不会挤占 AI 主模型和回退模型的审核时间。

全局 AI 内容审核在“运行配置”顶部的独立面板中统一配置：选择一个主模型和最多 3 个有序回退模型，可用上移/下移按钮调整实际尝试顺序；即使某个历史回退模型暂时不可用，页面也会保留它在原来的优先级位置，恢复后不会悄悄重排。仅当上一个模型超时、报错或返回无效结果时才继续尝试。模型返回严格 JSON（例如 `decision`/`verdict`、`confidence`/`score`、`reason` 字段）时也会被安全解析；还可选择一个不与主模型或回退模型重复的二次确认模型，仅在初判 `BLOCK` 后独立复核；确认 `ALLOW` 时放行，确认失败时只记录、不撤回。所有模型共享 5-120 秒总超时，空异常也会记录可诊断的错误类型或超时原因。AI 默认要求模型返回带置信度的 `BLOCK` 且达到阈值（默认 95）才处理，并默认“只记录、不撤回”；确认模型稳定后可切换为“撤回消息”。普通聊天、轻度玩笑和游戏/动漫截图默认放行；是否把图片送给视觉模型可单独开启。若某个文本模型明确返回不支持视觉输入，会在剩余预算内对同一模型自动重试文字审核；普通网络/配额错误仍直接进入下一个回退模型，不会重复消耗预算。图片 OCR 关键词审核默认关闭，可配置全局关键词、OCR 模型、单条图片数和超时。全局文字关键词和全局图片关键词各自拥有独立的撤回回复与艾特开关；回复模板留空且关闭艾特时不发送提示。禁言回复支持 `{at_user}`、`{duration}`、`{expire_at}`、`{member_openid}` 变量；将 `{at_user}` 放在回复任意位置即可使用 QQ 官方 `<qqbot-at-user id="..." />` 艾特，不填写则不艾特。模型异常中的 URL、Bearer/API token 和 `sk-*` 密钥会在记录与日志中统一脱敏。

匹配到的全局策略中的成员黑名单会在对应群优先执行，即使单群消息审查关闭也会撤回命中成员的消息；黑名单回复和艾特开关独立配置。全局 AI 审核对所有已绑定群生效，不依赖单群消息审查开关；群主、管理员和白名单成员仍按免审规则跳过。全局或单群成员白名单命中后跳过该成员的常规消息审查，但仍允许关键词回复；黑名单优先于白名单。名单支持逗号、空格或换行分隔，填写已绑定 UID 时会自动映射到对应成员。

“全局规则”按已绑定群名称多选覆盖范围，不需要手填 OpenID。每条规则可自定义名称、填写多个关键词、选择“全部满足/任一满足”以及“包含/完全匹配”；不选择群时覆盖全部已绑定群及以后新增的群。单群规则在“群管理”中编辑并优先于全局规则，同一条消息只执行首个匹配项。对应群级策略可设置按群冷却时间和回复自动撤回时间。关键词回复不要求开启消息审查，但 QQ 开放平台仍需开启“接收所有群消息”，否则机器人只能响应 @机器人的消息。

“启用审核设置命令”默认开启；关闭后群内 `/审核设置` 不会发送面板，可在 WebUI 的“运行配置”中重新开启。

## 群消息审查

每个已绑定群都可以独立启用基础消息审查，并在群内 `/审核设置 -> 消息审查` 或 WebUI 中开关本群关键词；连续发图和复读检测由“运行配置”中命中的群级策略控制，不再受单群基础开关限制。AI 审核开关和模型使用全局单份配置。全局消息拒绝关键词优先于群级关键词；命中后立即停止后续插件和默认模型处理并撤回消息。单群文字关键词、图片文字关键词、全局连续发图和全局复读处置分别配置回复内容和是否艾特；全局图片关键词的回复和艾特也不继承文字关键词设置。

成员名单在这条链路中先于普通规则判断：黑名单命中会记录违规内容、发送独立提示并撤回当前消息；白名单命中则跳过关键词、图片、刷屏、复读和 AI 审核。名单只使用 QQ 事件能稳定取得的成员/联合 OpenID，或插件已经建立的一对一 B 站 UID 绑定，不尝试通过 QQ 号码猜测成员身份。

- AI 审核只处理未命中本地规则的消息；对已绑定群不受单群消息审查开关影响。主模型仅在异常、超时或输出没有以明确 `ALLOW`/`BLOCK` 决策开头时按顺序调用全局回退模型；`BLOCK` 还必须带置信度并达到阈值，明确 `ALLOW` 保守放行。总超时初审阶段只在当前主模型和剩余回退模型之间分配；确认模型仅在初判 `BLOCK` 后使用截止时间内的剩余预算，避免主模型被过早取消。配置二次确认后，只有初判和复核都达到 `BLOCK` 阈值才执行所选动作；复核故障只记录、不撤回。默认命中只写入违规记录，不撤回、不计入 UID 违规次数；切换为撤回动作后才执行处置。模型说明文字中的 `BLOCK` 不会单独触发审核结论。
- 连续发图按命中策略的群分别统计成员链和跨成员纯媒体链，达到策略配置的数量、时间窗和人数条件后最多撤回指定数量的消息并发出警告；普通文本会打断连续链，不会把不同图片当作相同复读内容。
- 全局消息频率限制默认关闭；开启后按命中策略的群和成员统计时间窗内普通消息，达到阈值时最多撤回指定数量的最近消息并发送独立提示。管理员、白名单成员和带命令消息不累计，窗口队列有固定上限。
- 图片文字审核只有在全局 OCR 开关开启且配置关键词时才运行；QQ 原生表情名称会先参与关键词匹配，内联 GIF 在送入视觉模型前转换为受支持的 PNG 首帧，远程 GIF 或 QQ GIF 附件不会直接送入不兼容的视觉模型。本地 OCR/视觉 OCR 任一失败均不阻断消息，避免网络或模型异常造成误撤回。
- `/撤回` 只使用插件收到的最近 120 秒消息 ID，按 QQ 单条撤回接口逐条执行；重启、未接收的消息和超过 2 分钟的消息无法补查。
- 不同普通成员连续发送相同内容达到策略阈值后撤回该轮消息，从参与者中随机选择一人，并在策略配置的最短/最长秒数区间内随机禁言；禁言成功后发送独立的“复读禁言后提示”，支持 `{duration}` 和 `{at_user}`，任意不同内容会打断当前复读序列。
- 刷屏和复读窗口使用有上限的内存队列，并在时间窗外及时淘汰记录；AI 回退链、违规记录和轮询任务也设有数量/时间上限，避免长期运行持续增长资源占用。AI 图片最多预处理 3 张，本地 OCR/图片转换使用单并发闸门，繁忙时跳过媒体处理并继续文字规则；媒体超时后闸门会等底层任务真正退出再释放，避免慢任务叠加占用线程。AI 并发繁忙时直接失败开放，不让请求排队拖满总超时。
- 默认不审查群主、管理员和机器人自身消息。QQ 开放平台必须开启“接收所有群消息”，否则插件只能看到 @机器人的消息。

## 真人验证与 UID 身份

当自动审核条件未通过但兜底动作选择“同意”时，可开启兜底真人验证。用户入群后会被标记为可疑；验证前发送的消息会被撤回，并依次收到用途说明文本与仅本人可点击的算式按钮卡；看不到按钮时直接发送正确数字即可，答对后恢复正常。

验证提示会明确说明验证用途、点击正确答案和未完成验证的处理方式；这些说明也会放在按钮卡片正文中。按钮未显示、客户端不支持或发送按钮权限不足时，群内会改发包含完整说明和算式的文字，用户直接发送纯数字即可；带有“答案”或“验证”等前缀的文本不会通过。验证题仅在插件处理的审批成功后创建，避免普通群事件缺失造成误标记。

入群欢迎规则在 WebUI 的“运行配置 -> 入群欢迎”中配置。可以添加多条规则、选择全部已绑定群或指定多个群，并设置 `{at_user}`、`{user}`、`{username}`、`{group_name}`、`{group_openid}`、`{member_openid}`、`{uid}` 变量和单条消息自动撤回时间。欢迎消息只在自动审核或管理员按钮审批成功后发送；AstrBot 当前 QQ 适配器未转发普通成员加入事件，因此不会额外轮询群成员列表。

通过 B 站 UID 审核的用户会与 UID 绑定。同一个 UID 只能绑定一个 QQ 联合身份；冲突申请会被拒绝。WebUI 的身份记录可查看 UID、关联群和违规次数，也可以手动解除绑定；可疑用户列表支持管理员手动解除状态。每次消息审查违规都会保存有限长度的原文、命中规则、处理时间、成员/联合 OpenID 和群信息；违规记录最多保留 2,000 条。身份绑定最多保留 20,000 条、待验证成员最多保留 10,000 条，超限保留最新记录，成员查找使用索引，避免长期运行持续扫描。身份页通过服务端按名称、UID、OpenID、群或违规内容搜索，并分别分页返回身份绑定、待验证成员和违规记录；可选择每页 10、20 或 50 条，不会在打开页面时一次传输整张记录表，首次进入身份页才发起查询。绑定列表按数字 UID 顺序排列，旧状态里的异常时间值会安全降级。违规记录带稳定 ID 和人工复核状态，可筛选待复核、确认违规或误判；人工复核只影响记录管理和查询，不会自动学习关键词、不改变 UID 违规次数。违规记录可按当前搜索及状态条件导出为带公式注入防护的 UTF-8 CSV。

旧版身份快照兼容：仅保存 `members` 群成员映射的 UID 绑定会在身份页展示和搜索时自动恢复群范围；绑定和待验证记录会保存群 OpenID 对应的历史群名，即使群配置被删除、重建或暂时没有群名也能按原群名查询；旧待验证记录也会从现有 UID 绑定补齐 B 站 UID，并优先保留历史群名；缺少记录 ID 的旧违规数据会在首次读取后按节流策略补齐并持久化，避免重启后记录链接变化。

## B 站推送

每个群可绑定多个 UP 主 UID，并分别启用直播和动态推送。直播状态使用 B 站匿名批量接口，不需要 Cookie；动态推送需要 B 站登录态并通过 WBI 签名访问。在 WebUI 的“运行配置”点击“扫码登录”即可用 B 站客户端确认登录；Cookie 只保存在 AstrBot 插件配置中，不会通过 Web API 回显，也不会写入插件日志或群消息。

首次成功轮询只建立状态，不补发历史动态或当前直播。后续会推送新动态、开播和下播；消息优先使用插件本地生成的 720px B 站图片卡片，按作者、类型、时间、正文和封面分层，底部只保留清晰的“查看原动态”入口，并在同一条富媒体消息中保留原动态 URL。远程 T2I 仅作为兼容兜底；本地卡片、T2I、图片上传或权限不可用时再回退为 Markdown，最后发送纯文本命名链接。同一 UID 被多个群订阅时只请求一次再分发；接口返回的占位横线会被清理，图文和转发动态会尽量提取嵌套封面。网络失败、限流或风控不会清空游标，也不会误报下播。

## 自动审核

`/自动审核开启 123456,789012` 会为当前群创建 QQ 官方白名单自动审核策略。白名单中的后续入群申请由 QQ 平台自动通过，不依赖 AstrBot 入群事件，也不需要插件后台轮询。

开启策略或添加白名单后，插件还会调用官方执行接口，异步扫描当前待审申请。QQ 官方预计约 10 分钟完成，暂未提供任务进度查询接口。

插件只操作当前群的单群 OpenID 策略，并隐藏策略 ID、群 OpenID 和开关等技术参数。如果检测到多个、跨群或按 QQ 群号关联而无法安全匹配的策略，会停止操作并要求先在 QQ 官方后台整理，避免影响其他群。

如果当前群已经存在未由 WebUI 配置管理的策略，WebUI 同步会拒绝接管。确认旧策略可以删除后，先发送 `/自动审核关闭 确认`，再重新同步。

白名单单次最多提交 10,000 个 QQ 号码，单个策略最多 100,000 人。官方返回的白名单人数是估算值。

条件审核会读取用户主动入群申请的验证内容。全局拒绝关键词优先于群级硬拒绝关键词，两者都优先于其他审核条件。B 站 UID 与通过关键词可按“全部满足”或“任一满足”组合，也可开启“有效 UID 直接通过”来忽略通过关键词和组合结果；条件未通过时可选择保留待审、拒绝或同意。UID 接受 `UID:188144093`、`UID：188144093` 或纯数字格式，并通过 B 站用户名片接口核对返回值；B 站限流、网络错误或异常返回始终保留待审，避免误审。机器人邀请产生的申请不自动处理，可用 `/申请列表` 的按钮审核。

## 审批按钮

`/申请列表` 使用 QQ 原生回调按钮，只有 QQ 群主或管理员能点击，没有文字审批命令回退。按钮凭据 15 分钟后失效，AstrBot 重启后旧按钮也会失效，重新查询即可。

`/审核设置` 本身允许群成员唤出面板，但所有设置按钮均使用 QQ 的管理员按钮权限，普通群成员不能执行。首页按审核条件、消息审查、关键词回复和 B 站推送分层，避免按钮文字被 QQ 客户端截断；文本规则仍在 WebUI 中编辑。设置面板默认在发送 45 秒后自动撤回，可在“运行配置”中关闭。停用时仅删除本插件记录的 QQ 官方策略，不会接管或删除未托管策略。

AstrBot `4.27.3` 尚未公开按钮组件和互动事件插件接口，本插件在 QQ 适配器启动前启用互动 intent，并复用其 botpy 客户端发送键盘。插件只消费自己的按钮，其他互动事件会继续交给原处理器。首次安装、热重载插件或修改平台后请重启 AstrBot（或重载 QQ 适配器）；Webhook 模式还需在 QQ 开放平台订阅 `INTERACTION_CREATE`。该兼容桥已锁定 AstrBot `4.27.3 <= version < 5`，升级 AstrBot 后应重新验证。

## 能力边界

QQ 当前没有开放成员列表、踢人、管理员设置、修改群资料、查询或解除群黑名单、写入全员或定时禁言规则、群文件列表/删除等接口。本插件不会使用非官方协议补齐；`/全体禁言` 与 `/全体解禁` 只查询并报告该能力边界。群文件目前只支持通过 QQ 官方富媒体接口发送可公开访问的 URL，不读取本地路径，也不伪造文件列表或删除功能。

QQ 文档列出的入群申请事件尚未由 AstrBot `4.27.3` QQ 适配器转发到插件事件总线。QQ 号码白名单使用官方持久化策略；需要读取验证文字的 UID 模式则以 30 QPM 限额内的错峰轮询实现。

启用自动审核时，插件会先通过 QQ `bot_state.member_role` 校验机器人在该群的角色。若申请列表接口仍返回 `40011030`，警告日志会同时给出群名称、群 OpenID、平台实例和 QQ 返回的 `bot_role`；`bot_role=admin` 但申请接口仍拒绝时，说明 QQ 两个接口的权限状态不一致，应携带日志中的 `trace_id` 向 QQ 开放平台反馈。该错误码现在会显示为“入群申请接口判定机器人不是群管理员”，不会改变 QQ 的权限判定。
